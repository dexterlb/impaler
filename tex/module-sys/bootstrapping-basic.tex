\section{Bootstrapping basic constructs}
\label{bootstrapping-basic}
The base syntax of ILD is insufficient for writing nontrivial programs
in a succinct way. However, its \(\ildsf{macroexpand}\) facility allows
extending the syntax with arbitrary metaprogramming constructs, which can
be built incrementally.
In this section, we present a reference standard library
of such constructs, \paraphrase{culminating} in \ild{letrec}.
Keeping that complexity out of the core language makes it simple and portable
to different host environments.

\subsection{Lambda}
\label{lambda-macro}
First, we define a macro called \ild{lambda} that will let us introduce new
abstraction objects (\cref{abstraction}). We want expansion of the \ild{lambda}
macro to result in a call to \ild{mk-lambda} given the current binding environment
(\ild{free-vars}) and the quoted argument names and body (\cref{lambda-expansion-example}).
\begin{ildcode}
(!lambda (x y) (+ x y))
; should become
(mk-lambda (free-vars) (quote (x y))
  (quote (+ x y)))
\end{ildcode}
\lstcaption{Example expansion for \ild{!lambda} expression}\label{lambda-expansion-example}
A possible implementation of the \ild{lambda} macro is provided in \cref{lambda-macro-def}:
The outer call to \ild{mk-lambda} introduces a new \(\ildsetAbstr\)-object
carrying the current binding environment
% \footnote{
%   The \ild{(free-vars)} closure given to the host \ild{mk-lambda} can be replaced
%   by a closure that contains only \ild{cons}, \ild{mk-lambda}, \ild{quote} and \ild{free-vars},
%   since those are the only bindings used by the body of the macro.
% }
and a body. The body then, when called, in turn
expands to an expression embedding \ildhost{mk-lambda} in its head.
\begin{ildcode}
(mk-lambda
  (free-vars)
  '(arg-names body)
  '(cons mk-lambda
    (cons (cons free-vars '())
      (cons (cons quote (cons arg-names '()))
        (cons (cons quote (cons body '()))
          '())))))
\end{ildcode}
\lstcaption{Implementation of the lambda macro}\label{lambda-macro-def}
Embedding the values of \ild{mk-lambda}, \ild{free-vars} and \ild{quote}
avoids name shadowing problems traditionally encountered with unhygienic
macro systems (\cref{hygiene-discussion}).

\subsection{Basic utilities}
We define helper utilities in a scope where the \ild{lambda} macro is present.
To keep the code succinct, we store these definitions in separate bootstrap
source files and introduce them in scope with the same technique as the
\ild{lambda} macro.
\begin{ildcode}
; body of 'list'
(!lambda args args)

; body of 'cadr'
(!lambda (p) (car (cdr p)))

; body of 'caar'
(!lambda (p) (car (car p)))

; 'Y' is special case of poly-fix
(!lambda (f) (car (poly-fix f)))
\end{ildcode}
\lstcaption{Definitions of basic helper primitives}
To more easily write macros that generate expressions
of the form \ild{(!lambda <args> <body>)}, we define a helper
(\cref{def-expand-lambda}).
\begin{ildcode}
; body of 'expand-lambda'
(!lambda (args body)
  (cons macroexpand
    (cons lambda
      (cons args
        (cons body '())))))
\end{ildcode}
\lstcaption{Definition of \ild{expand-lambda}}\label{def-expand-lambda}

Since \ild{letrec} is not available at this point of the bootstrap process,
in \cref{def-map} we define \ild{map} via \ild{Y}.
\begin{ildcode}
; body of 'map'
(Y (!lambda (map)
  (!lambda (f l)
    (!if (null? l)
      l
      (!if (pair? l)
        (cons
          (f (car l)) (map f (cdr l)))
        (make-fail
          (list 'not-a-list l)))))))
\end{ildcode}

\subsubsection{Let}
The binding construct \ild{let} is simply a more ergonomic way
of writing a \ild{lambda} expression applied to a list of body expressions
(example in \cref{let-example}).
In \cref{def-let} we show how it can be defined via \ild{expand-lambda}.
\begin{ildcode}
; body of 'let'
(!lambda (letlist body)
  (cons
    (expand-lambda
      (map car letlist)
      body)
    (map cadr letlist)))
\end{ildcode}
\lstcaption{Definition of \ild{let}}\label{def-let}

\begin{ildcode}
; this program
  ((!lambda (add1 forty-two)
      (add1 forty-two))

      (!lambda (x)
        (add x 1)) ; definition of add1
      42)          ; definition of forty-two

; can now be written as
  (!let (
      (add1 (!lambda (x)
              (add x 1)))
      (forty-two  42))

    (add1 forty-two))
\end{ildcode}
\lstcaption{Rewriting a \ild{lambda}-based scope binding to use \ild{let}}\label{let-example}
To bind several names in sequence, where each binding may refer to the
preceding ones, in \cref{def-letstar} we define \ild{let*} as a recursive
macro function via \ild{Y}, similarly to \ild{map}.
\begin{ildcode}
; body of 'let*'
(Y (!lambda (let*)
  (!lambda (defs body)
    (!if (null? defs)
      body
      (list
        (expand-lambda
          (list (caar defs))
          (let* (cdr defs) body))
        (cadr (car defs)))))))
\end{ildcode}

\subsection{Letrec}
\label{letrec}
The low-level primitive for building mutually-recursive functions is
\ildsym{poly-fix}. \paraphrase{To provide convenient high-level syntax for this purpose},
in \cref{letrec-def} we define \ild{letrec} as a macro that:
\begin{itemize}
\item Builds a list of higher-order operators
from the familiar name/body pair syntax, and one extra
operator for the letrec body
\item Generates an expression that:
  \begin{itemize}
  \item Obtains a list of resulting recursive functions, one for each definition, via \ildsf{poly-fix}
  \item Applies the body operator to that list of functions
  \end{itemize}
\end{itemize}

\begin{ildcode}
; body of 'letrec'
(!lambda (defs body)
  (!let* (
    (names (map car defs))
    (bind-operators
      (map
        (!lambda (def)
          (expand-lambda names (cadr def)))
        defs))
    (body-operator
      (expand-lambda names body)))

    (list
      apply
      body-operator
      (cons poly-fix bind-operators))))
\end{ildcode}
\lstcaption{Definition of letrec}\label{letrec-def}
As defined in \cref{letrec-def}, \ild{letrec} has similar semantics
to \code{letrec} in Scheme, which also requires that definition bodies
can be evaluated without referencing the other bindings~\cite{r5rs}.
