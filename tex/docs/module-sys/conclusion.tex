\section{Conclusion}
The programming language ILD, presented in this paper, uses callsite-triggered
expansion of first-class macros to support modular, statically-scoped programs
without mutation of a global environment. Its semantics (summarised in
\cref{stepped-semantics-fig}) is minimal: the only possible \emph{combination}
steps are function application and one of the three special forms. Together
with a set of host functions and data structures, provided via FFI, and a
metaprogramming library written in ILD itself, it lets the user write modular
programs with named functions, mutual recursion and source imports, none of
which is built into the base language. Macros being ordinary first-class
functions called at runtime allows for a simple evaluator with no separate
macro expansion phase. The macros in this paper make use of this runtime
semantics to emit values instead of keywords, which avoids name capture and
leakage without hygiene machinery. In the future we aim to improve performance
by employing partial evaluation as an optimisation step.
