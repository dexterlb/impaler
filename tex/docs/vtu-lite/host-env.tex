\subsection{A minimal host environment}
\label{root-env}

The base language, as defined in \cref{semantics}, cannot express useful programs on its own. In this section we constrain
\(\ildsetHost\) to contain data structures, functions and constants that allow implementing nontrivial
programs. To make these values available to programs, we also define a root binding environment \(E\)
that is used for the outermost eval.

We will use the following notation
to define the semantics of the host functions:
\begin{equation}
  \denotdefas{\denotapply{\ildsym{foo}}{x_1}{\dots}{x_n}}{E}{y}
\end{equation}
Formally, the aforementioned notation introducing \ildsym{foo} is shorthand for:
\begin{itemize}
  \item \(\ildhost{foo} \in \ildsetHostFunc\) -- introduce a \(\ildhost{foo}\) \emph{host function}
  \item \( \denotapply{\ildhost{foo}}{x_1}{\dots}{x_n} = y \) -- assert that \(\ildhost{foo}\) applied to \(x_1, \dots, x_n\) results in \( y \)
  \item \(E = \ildlist{\dots}{\ildpair{\ildsym{foo}}{\ildhost{foo}}}{\dots}\) -- assert that the symbol \(\ildsym{foo}\) stands for the host value \(\ildhost{foo}\) in the root environment \(E\)
\end{itemize}
For example, to introduce the function \ildhost{cons} under the symbol \ildsym{cons}
in the root environment, we would write:
\begin{equation}
  \denotdefas{\denotapply{\ildsym{cons}}{a}{d}}{E}{\ildpair{a}{d}}
\end{equation}

\subsubsection{Basic data structures}
ILD's FFI semantics allows externally providing any data structure to ILD programs.
The base environment presented here provides numbers, booleans and strings
(\(\ildsetNum, \ildsetBool, \ildsetStr \subset \ildsetHost\)), and is sufficient
for demonstrating expressivity. Standard functions on such values, as well as
operations on S-expressions, are also provided through the FFI (\(\ildsetHostFunc\)):
\begin{itemize}
  \item Arithmetic: \(\ildapp{+}{x_1}{\dots}{x_n}\), \(\ildapp{*}{x_1}{\dots}{x_n}\),
    \(\ildapp{-}{x}{y}\), \(\ildapp{/}{x}{y}\)
  \item Comparison: \(\ildsym{=}\), \(\ildsym{<}\),
    \(\ildsym{>}\), \(\ildsym{<=}\), \(\ildsym{>=}\)
  \item Pairs: \(\ildsym{cons}\), \(\ildsym{car}\), \(\ildsym{cdr}\)
  \item Constructor for lists: \(\ildapp{list}{x_1}{\dots}{x_n}\)
  \item Value type predicates: \(\ildsym{null?}\), \(\ildsym{pair?}\),
    \(\ildsym{symbol?}\), \(\ildsym{string?}\), \(\ildsym{func?}\),
    \(\ildsym{fail?}\)
  \item Equality: \(\ildapp{sym-eq?}{s_1}{s_2}\), \(\ildapp{str-eq?}{s_1}{s_2}\)
  \item Failure: \(\denotdefas{\denotapply{\ildsym{make-fail}}{v}}{E}{\ildfail{v}}\)
\end{itemize}

\subsubsection{Special forms}
Access to the special forms is provided via symbols in the root environment:
\begin{equation}
  \begin{array}{@{}l@{}}
    E = ( \\
    \quad \dots \\
    \quad \ildpair{\ildsym{quote}}{\ildsf{quote}} \\
    \quad \ildpair{\ildsym{macroexpand}}{\ildsf{macroexpand}} \\
    \quad \ildpair{\ildsym{free-vars}}{\ildsf{free-vars}} \\
    \quad \dots \\
    )
  \end{array}
\end{equation}

\subsubsection{\texorpdfstring{\(\lambda\)-abstractions}{lambda-abstractions}}
\label{abstraction}
User-introduced functional objects in the host environment are
represented as \(\ildsetAbstr\)-terms. Each such term carries a binding environment \(e\),
a list of formal parameters \(P \in \ildsetSymList\) and a body expression
\(\beta\), and is \emph{applied} by substituting the formal parameters by the
actual parameters in the local binding environment,
and then evaluating the body in the resulting environment:
\begin{equation}\begin{gathered}
  \denotapply{\ildabstr{e}{P = \ildlist{p_1}{p_2}{\dots}{p_n}}{\beta}}{a_1}{a_2}{\dots}{a_n} = \denot{e'}{\beta}
  \\
  \text{where } e' = \spacedlist{e}{\subst{p_1}{a_1}}{\subst{p_2}{a_2}}{\dots}{\subst{p_n}{a_n}}
\end{gathered}\end{equation}
Formally, parameter substitution in a binding environment \(e\subst{x}{v}\) is defined as:
\begin{equation}
  e \subst{x}{v} =
  \begin{cases}
    \ildpair{\ildpair{x}{v}}{()} & e = () \\
    \ildpair{\ildpair{x}{v}}{e'} & e = \ildpair{\ildpair{x}{w}}{e'} \\
    \ildpair{\ildpair{y}{w}}{e' \subst{x}{v}} & e = \ildpair{\ildpair{y}{w}}{e'} \land y \neq x
  \end{cases}
\end{equation}
To let programs build such \(\ildsetAbstr\)-objects, we provide a data constructor:
\begin{equation}
  \denotdefas{\denotapply{\ildsym{mk-lambda}}{e}{P}{B}}{E}{\ildabstr{e}{P}{B}}
\end{equation}

\subsubsection{Branching}\label{branching}
The boolean datatype is of no use on its own without a function that
distinguishes between its values. Thus, we provide
the \ildsym{bool-to-k} function that transforms a boolean into
an argument selector:
\begin{equation}
  \denotdefas{\denotapply{\ildsym{bool-to-k}}{b}}{E}{
      \begin{cases}
        \ildabstr{()}{\ildlist{x}{y}}{x} & b = \ildhost{t} \\
        \ildabstr{()}{\ildlist{x}{y}}{y} & b = \ildhost{f} \\
      \end{cases}
  }
\end{equation}
This allows the base language to delegate branching entirely to the host
implementation of the boolean datatype. The \ildsym{bool-to-k}
function can then be used to build higher-level branching primitives
(e.g. \cref{if}).

\subsubsection{A recursion operator}

We provide a low-level operator \ildsym{poly-fix} for constructing
mutually-recursive functions:
\begin{equation}
  \denotdefas{\denotapply{\ildsym{poly-fix}}{\Gamma_1}{\Gamma_2}{\dots}{\Gamma_n}}{E}{\ildlist{\ildconst{f}{1}}{\ildconst{f}{2}}{\dots}{\ildconst{f}{n}}}
\end{equation}
When evaluated, \ildsym{poly-fix} introduces the functional objects \(\ildconst{f}{1}, \dots, \ildconst{f}{n}\) whose semantics are:
\begin{equation}
  \denotapply{\ildconst{f}{i}}{a_1}{\dots}{a_k}
  = \denotapply{f_i}{a_1}{\dots}{a_k}
\end{equation}
where \( f_1 \dots f_i \) are intermediate recursion results of the fixed point:
\begin{equation}
  f_i = \denotapply{\Gamma_i}{\ildconst{f}{1}}{\ildconst{f}{2}}{\dots}{\ildconst{f}{n}}
\end{equation}

\subsubsection{Interpreter access}
It is practical to allow programs to call into the interpreter:
\begin{equation}\begin{gathered}
  \denotdefas{\denotapply{\ildsym{apply}}{f}{\ildlist{a_1}{\dots}{a_n}}}{E}{\denotapply{f}{a_1}{\dots}{a_n}}\\
  \denotdefas{\denotapply{\ildsym{eval}}{e}{v}}{E}{\denot{v}{e}}
\end{gathered}\end{equation}
Furthermore, to allow programs to reference other programs, we provide
a host function \ildsym{read-source} that retrieves a program by name.
In real-life implementations, \(\ildapp{read-source}{p}\) will read
the file whose path is \(p\), parse its contents and return the resulting value.
